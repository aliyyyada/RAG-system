# Протокол источника документов (допущение)

Настоящий формат функции источника ещё неизвестен (open-questions #7). Пока работаем по
протоколу ниже: его понимает адаптер `http_json` (`backend/app/sources/http_json.py`), на нём
говорит фейковый источник (`backend/fakes/fake_source.py`). Когда разработчики источника
пришлют свой формат, меняется только адаптер: синхронизация, проверки полноты и отчёт
работают через интерфейс `DocumentSource` и не меняются.

Все запросы — `GET` по HTTPS, ответы — JSON в UTF-8. Даты — ISO 8601 **с часовым поясом**
(`2024-05-20T08:42:00+03:00`). Адрес API задаётся в настройках источника, например
`https://docflow.zavod.local/api/rag`.

## 1. Список документов

```
GET {адрес}/documents?modified_since=2026-10-31T10:00:00+03:00&cursor=<…>&limit=500
```

- `modified_since` — только документы, изменённые не раньше этой даты (инкрементальная
  синхронизация, каждые 15 минут). Без параметра — **все** документы, включая удалённые
  (ночная сверка).
- Порядок — по дате изменения, затем по id. `cursor` — непрозрачная строка из предыдущего ответа.

```json
{
  "items": [
    {"id": "5ef9…dbc5", "modified_at": "2024-05-20T08:42:00+00:00", "deleted_at": null},
    {"id": "1a2b…9f00", "modified_at": "2021-01-01T00:00:00+00:00", "deleted_at": "2021-01-01T00:00:00+00:00"}
  ],
  "next_cursor": "500"
}
```

`deleted_at` не пустой — документ мягко удалён в источнике, у нас он пропадает из поиска.

## 2. Документ целиком

```
GET {адрес}/documents/{id}
```

```json
{
  "header": {
    "id": "5ef9…dbc5",
    "modified_at": "2024-05-20T08:42:00+00:00",
    "deleted_at": null,
    "doc_type": "Приказ",
    "number": "112",
    "date": "2024-03-14",
    "title": "О допуске персонала к работам на высоте",
    "topic": "Охрана труда",
    "department": "Служба ОТ и ПБ",
    "любое другое поле": "попадёт в текст документа как «любое другое поле: …»"
  },
  "parts": [
    {
      "name": "Ознакомлены",
      "row_count": 46,
      "rows": [
        {"document_id": "5ef9…dbc5", "personnel_number": "20871", "full_name": "Петров В. Н.", "acquainted_at": "2024-03-15"}
      ]
    }
  ],
  "files": [
    {"id": "f-001", "name": "prikaz_112.pdf", "size": 51692, "mime": "application/pdf"}
  ]
}
```

- `parts[].row_count` — сколько строк **должно** быть. Не совпало с числом в `rows` —
  ошибка «Проверка полноты», документ не загружается, пока источник не дошлёт все строки.
- `files[].size` — размер в байтах. Не совпал со скачанным — та же ошибка.
- 404 — документа больше нет (у нас помечается удалённым).

## 3. Файл

```
GET {адрес}/files/{id файла}     → байты файла (PDF или DOCX)
```

Тип определяется по содержимому, а не по расширению. Больше `SOURCE_FILE_MAX_MB` (200 МБ) не скачиваем.

## 4. Общие документы

```
GET {адрес}/access/common         → {"ids": ["…", "…"]}
```

Документы из этого списка доступны всем, в том числе без входа.

## 5. Права пользователя на документы

```
GET {адрес}/access/users/{табельный номер}   → {"ids": ["…", "…"]}
```

- Список guid документов, которые источник разрешает этому человеку. На одного человека
  может прийти несколько тысяч id — это нормально (≈ 200 КБ JSON на 5 000 id).
- 404 — источник не знает такого человека: у него нет прав на документы источника (не ошибка).
- Таймаут (`ACCESS_TIMEOUT_SECONDS`, 5 с), ответ не 200/404 или не JSON — «источник не отвечает»:
  документы этого источника человеку не показываем (fail-closed), он видит предупреждение
  «Документы из системы X сейчас недоступны». Повторно спрашиваем через `ACCESS_RETRY_SECONDS` (30 с).
- Ответ кэшируется на `ACCESS_CACHE_MINUTES` (5 минут), кэш сбрасывается при входе человека
  и кнопкой в админке. Общие документы (раздел 4) сюда включать не обязательно.

## Ошибки и доступность

Таймаут (`SOURCE_TIMEOUT_SECONDS`, 30 с), ответ не 200/404 или не JSON — «источник не отвечает»:
синхронизация записывает ошибку в журнал, ничего не удаляет и повторяется по расписанию.

## Обратный API: что у нас загружено

Источник может спросить нас (токен выпускает администратор на странице источника):

```
GET  https://<наш сервер>/api/integration/v1/sources/docflow/documents?cursor=&limit=1000
POST https://<наш сервер>/api/integration/v1/sources/docflow/documents/lookup   {"ids": ["…"]}
Authorization: Bearer src_docflow_…
```

По каждому документу: `source_version` (последняя версия, которую мы видели), `indexed_version`
(версия, которая сейчас в поиске), `status` (`queued`, `processing`, `ready`, `error`, `deleted`,
`unknown`) и текст ошибки.
