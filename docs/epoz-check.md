# Проверка ЕПоЗ

Навык `epoz_check` (вкладка «Проверка ЕПоЗ»): пользователь загружает файлы закупочного пакета,
система проверяет их по 20 критериям из задачи (блоки 1, 2, 5, 6) **только** по ЕПоЗ и загруженному
пакету. Код лежит в `backend/epoz/`, подробности по файлам — в `backend/epoz/README.md`.

## Как это устроено

1. **ЕПоЗ в базе.** Положение и Приложения 1–14 («Перечень изменений» не загружается) разбираются
   в пункты с восстановленной нумерацией Word («10.3.4»). Комплект — это *редакция*; действующая
   одна. Документы ЕПоЗ защищены: триггер PostgreSQL и проверки API не дают их удалить или исключить.
   Доступ задаётся одной группой на весь комплект.
2. **Замена редакции.** Администратор («Администрирование → ЕПоЗ») создаёт черновик, заменяет
   нужные файлы (остальные части наследуются), смотрит отчёт разбора и активирует. Старая
   редакция остаётся в архиве.
3. **ОКПД2.** Справочник загружается из Excel («Администрирование → ЕПоЗ → ОКПД2»), нужен для
   срока оплаты по Приложению 14.
4. **Проверка.** Файл → роль (договор, ТЗ, записка, расчёт НМЦ, запрос КП, КП, другое; роль
   предлагается по имени и содержимому, пользователь может поменять) → победитель КП → «Проверить».
   Задача `check_run` идёт в worker: разбор файлов (OCR для сканов), извлечение данных правилами,
   20 критериев. Модель используется только в 1.2 и 2.2 (цитаты проверяются дословно).
5. **Статусы:** «Соответствует», «Нарушение», «Предупреждение», «Нужна ручная проверка».
   Если данные не извлеклись (плохой скан, нестандартная форма), критерий получает «ручную
   проверку», а не выдуманный вердикт.

## Приватность

- Данные пакета привязаны к сессии входа и видны только автору (админ тоже не видит).
- Удаляются при выходе, закрытии или истечении сессии, через `CHECK_IDLE_MINUTES` простоя
  (по умолчанию 120) и кнопкой «Очистить»: строки БД, фрагменты и папка `/data/documents/checks/<id>/`.
- Документы пакета не попадают в общий поиск, список документов, граф и противоречия.
- В аудит пишутся только метаданные (число файлов, итог), без содержимого.

## Настройки

| Переменная | По умолчанию | Смысл |
|------------|--------------|-------|
| `EPOZ_USE_LLM` | `true` | использовать модель в критериях 1.2 и 2.2 |
| `CHECK_IDLE_MINUTES` | `120` | через сколько минут простоя проверка стирается |
| `CHECK_MAX_FILES` | `20` | файлов в одной проверке |
| `CHECK_MAX_FILE_MB` | `100` | размер одного файла |

Права: `epoz.manage` (администрирование ЕПоЗ и ОКПД2), `skill.epoz_check.use` (запуск проверки;
дополнительно нужен доступ к комплекту ЕПоЗ через группу).

## Известные ограничения

- На сканах таблицы позиций и расчёта НМЦ распознаются плохо: критерии 6.3–6.7 и сверка
  позиций ТЗ и записки уходят в «ручную проверку». Текстовые PDF/DOCX работают полностью.
- Группа заказчика (I/II) задаётся администратором один раз; пока она не задана, срок оплаты
  проверяется только по Приложению 14.
- Блоки 3 и 4 задачи в реализации отсутствуют (допущение).
